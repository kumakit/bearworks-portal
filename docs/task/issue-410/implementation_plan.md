## 3. Phase 0：比較の成立性を決める

開始時に下記の地図基準と小人口基準を `feasibility.md` に記録し、取得・集計結果を見て都合よく緩めない。作業順は対象日と総数 → 利用・配布可否 → 年齢/地域対応 → 地図採否とする。

1. **資料内部の対象日と総数を最初に検査する。** 2016-09-30/2026-09-30の人口/年齢Excelを主資料とし、表題・注記の対象日、総数の実在、両資料間の同一定義での一致を検査済み。年度名やページ更新日では代用しない。取得URL、取得日時、対象日、hash、版、シート/列/注記をmanifestに残す。CSV差は別途記録し、未解明の差を許容誤差や手補正で埋めない。
2. **公開配布物の可否を独立判定する。** 人口・年齢ともExcel系列を主資料とし、CSVは照合・感度確認のみ。Excel→正規化CSV変換を独立手順とし、原本/変換後hash、変換器版、シート/列対応を保持する。`.xls` はxlrd、`.xlsx` はopenpyxl、Python 3.12以上＋uvを採用済み。利用条件上のallowと、配布予定物の範囲を分け、原本はローカル保存を基本とする。
3. 日本人のみ／外国人込み、男女合計、全市総計と町丁行、小計、年齢不詳の区別を確認。住民基本台帳と国勢調査を混ぜない。総計・男女別・外国人内数などを重複加算しない。年齢が1歳刻みか5歳階級か等を調べ、15歳・65歳の境界をまたがず厳密に3区分を作れるか確認する。できなければ別の公式年齢表 → 共通に再集計可能な年齢区分 → 年齢図の対象期間変更の順で代替を検討し、r2で明記する。階級内の人数を比例配分して3区分を捏造しない。
4. 両年の町丁一覧を比較し、町名の表記正規化と地域変更を区別する。コードがあれば優先し、コードの存在や年度間の安定性は仮定しない。旧名・新名・根拠URL・処理区分を対応表に残す。曖昧一致を自動採用しない。
5. 全市の同一定義の各年9月末推移を確保する。連続して比較可能な年だけ採用し、欠けた年は補間せず切れ目を示す。「いつから減少したか」は採用した時点間に限定して述べる。
6. 2016-09-30→2026-09-30はExcel系列で成立したため採用する。今後の改訂等で不成立となった場合の代替は2016→2025（9年）、2015→2025（10年）、2016年3月→2026年3月（年度末）の順を候補とする。2025年人口/年齢表は検算済み、2015年/年度末の両端比較は未検証。代替へ変更する際は期間と失う観点を記録し、異なる日付を同じ比較図に混ぜない。
7. e-Stat等の公式境界を対象地域だけ取得し、境界年・コード・名称・統廃合・飛び地・1対多の対応を調べる。名称一致だけを地理的一致の証拠にしない。人口の面積比例配分は行わない。

### 利用条件・公開配布ゲート

- manifestに `licenseName`、`licenseUrl`、`licenseCheckedAt`、`attributionText`、`modificationNotice`、`redistributionDecision`（allow/deny/unknown）、`decisionEvidenceUrl`、`allowedPublicArtifacts` を必須とする。採用資料への適用を確認したCC BY 4.0の表示文言をattributionTextへ実際に記載する。非該当資料にはその利用条件を記録し、CC BYを一律に付けない。
- 原本、正規化CSV、集計表/JSON、境界原本、簡略化境界/SVGを別々に判定し、チェック済み一覧を `feasibility.md` に残す。allow以外は公開可能リストへ入れず、`public/`・公開Git・ビルド配布物へ含めない。
- 人口資料の再配布だけ不可なら、許される集計結果と公式取得URL・変換手順で再現性を確保する。集計結果の公開も不明ならその資料に基づく公開を保留する。
- e-Stat等の境界条件が合わなければ地図表示と境界由来の配布物の両方を見送る。別の利用可能な境界候補がなければ、人口データに基づく比較チャートへ移行する。
- 「ライセンス名を見つけた」だけで通過にしない。対象資料への適用、必要な帰属/改変表示、公開予定物ごとの判断が揃ったことを完了条件にする。

### 地図採用の判断（r2で不採用。以下は判定記録と将来再採用時の基準）

- 人口カバー率の分子は両時点で同じ比較可能・境界確認済み地域集合を使う。公式行が秘匿・合算されている場合も、分母から都合よく除かず構成を記録する。必要な分母自体が確定できない場合は判定不能として地図を採用しない。
- 次の事前基準をすべて満たす場合のみ地図採用候補とする。95%は公式基準ではなく本記事の編集上の最低条件で、正確性を保証する数値ではない。
  1. 両時点それぞれ、比較可能かつ境界対応を確認できた地域の人口合計 ÷ 同一定義の公式全市人口が95%以上。
  2. 両時点それぞれ、比較・境界対応を確認できた公式町丁行数 ÷ 総計/小計を除く全公式町丁行数が95%以上。集約した地域は元の各行へ追跡し、集約単位の個数で分母を縮めない。
  3. 境界結合する前の比較可能地域全体で、人数差の増加上位10・減少上位10と、始点100人以上の増減率の増加上位10・減少上位10の全地域が結合済み。該当が10未満なら全件、境界順位の同順位も全件を対象とする。
- 件数結合率と両時点の人口カバー率、分母、未結合一覧、除外理由、閾値判定を保存する。町丁比較自体が不可能な地域はランキングに入らないため、両時点の人口規模と除外理由を別途確認し、全体像を歪める可能性が解消しなければ地図不採用とする。
- 着色する全地域で、比較期間の地域対応と境界対応に説明できる根拠があること。数値的な結合率が高くても曖昧な地域は着色しない。
- 未対応地域が特定地区へ偏っていないかも確認し、記事に対象外の範囲を明記する。95%以上でも全市の町丁すべてを網羅した図とは呼ばない。
- 境界変更は、公式根拠に基づき両時点を同一地域へ合算できるときだけ集約する。できなければ「比較対象外」。集約単位は町丁そのものと区別する。
- 主要な増減地域の位置が確定しない、除外が多く全体像を歪める、または利用条件を満たせない場合は、地図を見送り比較可能な地域のランキング＋比較チャートを主図にする。タイトルの「地図で見る」も変更する。
- 成果物: `feasibility.md`、出典manifest、地域対応表、地図採否と代替期間の決定記録。未確定事項を解決して計画r2を確定する。

閾値を変更する必要が生じた場合は、変更前後の判断と理由を残して計画を再レビューする。結果が通るように基準を後から緩めない。

## 4. Phase 1：取得・集計・検算

データフロー: 公式CSV/Excel・境界 → 保存原本＋manifest → 対象日と定義の検査 → 地域対応表 → 正規化データ → 集計と品質レポート → 固定JSON＋lock → 記事/図表。

- 取得と集計を分け、取得済み原本からネットワークなしで再生成できるようにする。取得エラーや資料改訂を黙って上書きせず版を残す。
- Phase 0で確定した変換構成を使う。xls/xlsxの解析にPythonを採用する場合はPython 3.12以上＋uvの小さなプロジェクトを `scripts/hachioji-population/` に置き、uv.lockで固定する。公開bundleの検証は既存Node環境へ接続する。Pythonは公開時ランタイムには不要。汎用ETL基盤にしない。
- 差 = 終点人口 − 始点人口、率 = 差 ÷ 始点人口 × 100。計算途中は丸めず表示時だけ丸める。
- 始点0の率はnull（算出不可）、欠測もnullだが理由コードを分ける。0→0も増減率0%にしない。欠測を0にしない。
- 小人口の事前基準は始点100人未満。人数の表示と一覧には残し、率ランキングの主表示から分ける。100人は編集上の区分であり統計的な保証ではない。50/100/200人の基準で順位が変わるかを補足検証するが、結果を見て主基準を選び直さない。変更が必要なら理由を記録し計画を再レビューする。
- 年齢3区分は0〜14/15〜64/65歳以上。年齢不詳があれば別欄を残し、構成比の分母（総人口または年齢判明人口）を明記する。人数差と構成比の差（ポイント）を区別する。
- 年齢区分ごとの増減を、その年齢層の人の転出入や同一集団の追跡と解釈しない。加齢による区分移動が含まれる。
- 整数人口の町丁合計と公式全市総計、各町丁の年齢合計＋不詳、重複/欠損/負値、両時点の地域キーを自動検査する。不一致は許容誤差で隠さず理由を調べ、説明不能なら生成を失敗させる。
- 「全町丁の全市総計」と「比較可能地域の小計」を別に保持。除外後の小計を市全体として表示しない。
- 研究メモで観測事実／解釈／確認できないことを分ける。原因や集計逆転は実際に追加検証できた場合のみ述べる。

### PR分割（r2）

- PR1: データ取得・変換・集計、検算テスト、manifest/利用条件、再現手順。許可のない原本をcommitしない。
- PR2: PR1を前提に、記事、固定bundle、図表、記事表示の検証と必要なCIを追加。
- PR3: PR2を前提に、新規 `/labs`、トップ、気候記事、site-contentの導線と統合検証を追加。

レビュー単位を分けても、公開単位は記事・導線・出典・再現手順がそろった1回とする。**PR1を含む最初のmain merge前に**、GitHub ActionsだけでなくCloudflare Workers/PagesのGit接続、対象branch、build trigger、その他公開経路を確認し、確認日時と秘密値を除く証拠を記録する。現在外部設定は未確認で、自動公開なしとは扱わない。

### 公開と復旧
