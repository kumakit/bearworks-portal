タイトル、概要、本文、図表、クイズ、診断、構造化データ、SNS用説明を対象に「主張 / 対象期間 / 定義 / 分子・分母 / データ種別 / 算出箇所 / 判定 / 修正案」の対応表を作る。

### A2. 取得原本・集計・表示の整合を確定する

- 公開対象として保存可能な取得原本の有無を確認する。未保存なら、既存集計から再現できる範囲とできない範囲を明記する。
- 原本の再取得が必要な場合は取得日時、APIパラメータ、モデル指定、タイムゾーン、返却された地点/標高、単位、欠測、原本ハッシュを保存する。再取得値が旧集計と異なる可能性を残し、2026-09-17の原本と同一とは記載しない。
- 原本の保存と同時に、同一取得処理でペアのメタデータJSONを機械保存する。schema version、原本ファイル名・バイト数・SHA-256、取得日時（UTC）、秘密値を除いた取得先/パラメータ、指定モデル、返却モデル情報（取得できない場合は未取得と明示）、タイムゾーン、地点・標高、単位、取得処理の版を記録する。人手での転記は必須証跡にしない。
- メタデータと原本のどちらかが欠ける、必須項目が不明なまま省略される、ハッシュが一致しない場合は、その組を正式な再集計入力として採用しない。検証処理でペアの存在、原本の生バイト数・SHA-256、予定した取得条件との一致を機械確認する。検証済みの組を入力にして集計し、成果物から対応する入力を追跡できるようにする。この補足のために保存サービスや新しい基盤を導入しない。
