### 評価と反映結果

1. **P0の評価**:
   - 逆302の撤回、新URL維持型復旧方針、301保存ブラウザでの検証条件は妥当と評価。
   - 復旧手順および301保存ブラウザでの復旧実証を、本番移行前（Gate 2 ステージングQA）の必須通過条件として前倒し反映。
2. **P1（Gate 1A 実装・完了条件）**:
   - **サーバー確認の具体化**: `getDoc()` のキャッシュリスクを排除するため、`getDocFromServer()` の採用を明記。
   - **世代管理と非同期キャンセレーション**: ユーザー切替・ログアウト時に古い読込結果によるLocalStorage更新・書き込み・ロック解除を破棄する世代管理（generation counter / AbortController）を設計・タスク化。
   - **同期処理失敗試験（モック）**: 認証済み状態から読込失敗を発生させ、書き込み（`setDoc`）が一度も呼ばれないことを確認するテスト要件を定義。本番Firestoreへの書き込みは一切禁止。
3. **P1（後続Gateの要件）**:
   - **Gate 3 mainマージ衝突防止**: 旧URL並行稼働中のmainマージを禁止。新URL用には固定プレビュー成果物をWorkerから配信。
   - **Gate 2 キャッシュ設定**: `cf.cacheTtlByStatus` により、200の静的アセットのみキャッシュし、エラーをエッジに保存しない設定を明記。
   - **Gate 5 個別301転送**: 包括転送を撤回し、URL旧新マッピング表に基づく個別転送ルールを確定。
   - **Gate 4 旧側試験停止**: basePathなしの旧成果物の更新デプロイ手順、120分猶予、未ログイン履歴制約の案内を定義。
4. **SEO・広告・P2**:
   - 広告方針（Toukeiアプリ配信画面は全面非広告）は採用可能。
   - サイトマップ（published概念88件、計123URL）は採用可能。
   - `/exam` のトップ（index）と動的試験中画面（noindex）の動的制御、staging noindex維持、canonicalタグ検証をタスク化。
