# Issue #397 Phase 3A: Cloudflare 画面の整理

作成日: 2026-10-14 JST
正本: https://github.com/kumakit/mission-control/issues/397

## 目的と確認した現状

Cloudflare 画面の通常表示を、利用できるアクセス推移と国別アクセスを中心にする。旧 WAF 5 項目、危険度の未実装カード、Pages の利用枠説明を主画面から撤去する。取得失敗や期限切れは引き続き見分けられるようにする。

認証済み本番画面で、24 時間・7 日・30 日の切替、アクセス推移、世界地図、国別一覧を確認した。7 日の前期間比と 30 日の比較不可表示も確認した。同じ画面の下部に、旧 WAF の取得失敗欄、危険度の未実装カード、Pages 当月デプロイ欄、常時展開された技術的な取得情報が残っている。これは Issue の更新後の通常表示要件と合わない。

既存の `CloudflareAccessView` が期間切替・グラフ・地図・一覧と項目ごとの利用可否を扱う。`CloudflareCollectionView` がその下に旧画面のカードを追加している。今回の変更対象は Portal の同コンポーネントと必要な表示テスト、文書に限る。

## 変更する内容

1. 通常画面は見出し・再読込、アクセス推移、国別アクセス、短い補足の順にする。`CloudflareAccessView` の集計値、選択操作、欠損時の表示は維持する。短い補足に「この画面はアクセスの推移と国別の表示で、セキュリティの判定は含みません」を加える。
2. 旧「必須データの状態」「危険度判定は次段階」「アクセス統計（24時間）」の重複欄、WAF 5 項目、Pages 当月デプロイを通常画面から外す。旧値を新しいアクセス値に流用しない。
3. 画面末尾に、初期状態を閉じた「データについて」欄を設ける。閉じた状態でもアクセス項目または Pages の失敗・期限切れがあれば「要確認」と分かる見出しにする。開くと、アクセス表示に使う項目の取得状態、ゾーン全体という範囲、期間の開始・終了（JST、内部判定は UTC）、集計方法と推計の有無、取得時刻・期限、固定文言に変換した失敗理由を確認できるようにする。国不明・地図外の地域も一覧と母数には残ること、30 日の前期間比は履歴未保存のため利用できないことを短く示す。`CloudflareAccessView` に既にある説明と重複する長文は増やさない。
4. Pages は Digest で今も必須であるため、利用枠の数値や判定は主画面から外し、「データについて」に「別の監視項目：Pages の取得状態」を補助表示する。アクセス項目の状態と合算しない。旧 WAF 5 項目は schema v2 の Digest 必須集合から既に除外されているため、通常表示とこの欄から外す。欄内に「Digest はこの画面とは別に、アクセス項目と Pages の取得状態を確認します。旧 WAF 詳細は必須監視対象ではありません」と示す。今回の表示変更後も、Apps 側の収集や Digest の判定は変えない。
5. API 全体の取得失敗は画面上部に今の警告を維持し、アクセスの値を表示しない。個別の期間・国別項目の失敗は、その項目だけを利用不可にする。選択中の期間は維持し、ほかの期間へ自動切替しない。比較元だけが失敗したときは比較だけを利用不可にする。旧形式や未対応形式も正常なゼロ値にしない。
6. 期限切れの判定は既存の `assessBlock` を使う。収集側が項目ごとに与える `validUntil` に、サーバー応答時刻と通信時間・許容誤差から計算した保守的な上限時刻 `nowUpper` が達したら「期限切れ」とし、その項目の値は表示しない。基準時刻を確認できない場合も値を利用しない。24 時間・7 日・30 日に画面独自の閾値は設けない。
7. 失敗理由は既存の `assessBlock` の安全な文言を再利用する。分類は権限または提供範囲、設定不足、時間超過、取得先の失敗、応答形式不正、原因不明、部分取得、未取得、期限切れ、不正な契約。未知のエラーは「取得できませんでした」または「未確認」とし、生の例外・内部 ID は表示しない。`ACCESS_DENIED` だけから権限不足と断定しない。
8. 収集契約、Apps の収集、Digest の必須判定、Cloudflare の設定・権限、他画面は変更しない。旧 WAF 5 項目を収集側で停止するかは、後続の運用整理で判断する。

## 別の作業に分けるもの

- セキュリティ推移は `firewallEventsAdaptiveByTimeGroups` の利用設定だけ確認済みで、返る値の意味、母集団、時刻境界、推計の扱いが未確認。小さな読み取り照会で確かめ、採用条件を満たした場合のみ別系列として追加する。旧 WAF 欄をそのまま復活させない。
- 30 日の前期間比と履歴保存は、ユーザーの指定に従い別フェーズとする。

## 確認方法と戻し方

- 合成データで各期間の推移だけの失敗、国別だけの失敗、24 時間・7 日・30 日それぞれの失敗、7 日の前期間だけの失敗、API 全体の失敗、期限切れ、時刻同期不可、旧形式を確認する。選択中の期間を維持し、ほかの値で補完しないことを見る。
- 旧 WAF・危険度・Pages 利用枠の欄が通常画面に出ないこと、Pages の取得失敗は「データについて」の閉じた見出しと開いた内容で分かることを確認する。`details` の標準の開閉状態とフォーカス表示、キーボード操作、スマートフォン幅、長い失敗理由での折り返しを確認する。型検査、対象テスト、lint、Workers CI を通す。
- ローカル表示を確認した後、PR の CI、本番配備、認証済み PC・スマートフォン表示を別々に確認する。配備後の収集・Digest の継続も別証跡として扱う。
- アクセスの正常値が消える、失敗・期限切れを正常に見せる、Pages の必須監視障害が追えない場合は公開を止めるか Portal の当該 PR を revert して再配備する。戻した旧画面は暫定表示とし、旧値を正常値へ補完していないこと、認証境界、Digest の継続を再確認する。収集契約や運用設定は巻き戻さない。
