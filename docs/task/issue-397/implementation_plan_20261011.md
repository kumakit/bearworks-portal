## 1. 目的と今回の範囲

Cloudflare を知らない利用者が、実際の HTTP リクエスト数の時間変化と接続元の国別分布をグラフ・世界地図から把握できる画面にする。確認できた事実を短い日本語で示し、取得できない値を 0、旧値、デモ値で埋めない。Free プランの現在の認証主体と zone で実測できたデータのみを通常画面へ採用する。

アクセス推移と国別分布の対象は、ユーザー確認により **bearworks.uk のゾーン全体（本体と各サブドメインを含む）** とする。期間・フィルタ・母数を揃え、本体ホストだけの集計を「全体」と表示しない。

標準表示順は、(1) 直近の数値カードとアクセス推移、(2) 世界地図と上位約 10 か国、(3) 採用可能な場合だけセキュリティの参考傾向、(4) 短い補足。期間選択は 24 時間・7 日間・30 日間の枠を設けても、各期間を個別に検証するまで操作可能にしない。選択期間、集計境界、更新時刻を表示し、「アクセス」は HTTP リクエスト数であって人数ではないと明記する。

旧 v4 計画で主役だった総合危険度、取得状態カード、WAF 5 項目、Pages 利用枠は今回の主画面の必須分析から外す。取得状態・鮮度・欠損の厳格な検証、Cloudflare Access、他サービスの監視は維持する。過去の実装・レビュー・配備の証跡は既存の `walkthrough.md`、`review-resolution.md`、Issue コメント、PR に残す。旧計画の受け入れ済み範囲を今回の受入条件へ機械的に引き継がない。

## 2. 確認した現状と未確認事項

- Apps の `dashboard/cloudflare_collect.py` は `httpRequests1hGroups` の時間別行を取得するが、現行 `traffic24h` 契約には合計値だけを格納する。Portal の `cloudflareCollection.ts` は schemaVersion 1 と固定の 7 ブロックを検証し、画面は 24 時間合計カードと WAF 詳細を前面に出している。
- 旧 WAF 5 項目の照会は `firewallEventsAdaptiveGroups` に依存し、Issue に実環境で利用不能との記録がある。`clientCountryName` は現在の上位 ASN 照会のフィールドであり、国別**アクセス**分布の根拠にはならない。
- Digest の `extract_dashboard_snapshot()` は `traffic24h` と `pagesMonth` の両方が利用できないと Cloudflare 未取得とする。この関数は旧 WAF 5 項目を直接判定していないため、実稼働版で `partial` を生む経路を Phase 0 で照合する。新しい監視対象に合わせるには、表示だけでなく収集契約・Digest 判定・回帰テストを一緒に変更する必要がある。
- 既存 Apps 認証主体の実測では、`httpRequests1hGroups` の完了 24 時間の時刻別値と `sum.countryMap` を同じ応答で取得でき、各時間の国別和が時間の全リクエスト数に一致した。7 日・30 日は `httpRequestsAdaptiveGroups` の時間別・国別を取得できたがサンプリングを含む。詳細は [Phase 0 証跡](./phase0-evidence-status_20261011.md)。
- `firewallEventsAdaptiveGroups` は現環境で `enabled=false`。`firewallEventsAdaptiveByTimeGroups` は `enabled=true` だが系列の意味を未検証。Natural Earth の利用条件は確認済みで、実地図ファイルの国コード対応は未確認。公式の保持期間拡張は全フィールドの利用可能性を保証しない。

## 3. Phase 0 — Free 実環境の読み取り調査

1. 現行 Apps 収集 → JSON → Portal API → 画面 → Digest の経路、旧国別表示の出所、収集間隔、実稼働版、対象 zone と認証主体の権限範囲を、秘密値を記録せず確認する。Apps の branch/HEAD/dirty 状態と Portal main との差分も固定する。
2. GraphQL `settings` で `httpRequests1hGroups`、`httpRequestsAdaptiveGroups`、候補のセキュリティデータセットについて `enabled`、`availableFields`、`notOlderThan`、`maxDuration`、`maxPageSize` 等を読む。小さな読み取り問い合わせで各候補のフィールド、24 時間・7 日間・30 日間の範囲と粒度、時間境界、返却行数、上限、サンプリング・推計の意味、遅延、レート制限を確かめる。可否表にはデータセット・期間ごとに、実測から判定した `exact` / `estimated` / `unknown` も記す。実測時は既存のトークンを使い、権限・契約・設定を変更しない。
3. **24 時間の国別は `httpRequests1hGroups.sum.countryMap` を第一候補**とする。時間別値と同じ照会・窓で、24 個の完了バケットの国別和と時間別総数の一致を各実行で確認し、国コードと地図素材の対応を固定する。7 日・30 日は `httpRequestsAdaptiveGroups.dimensions.clientCountryName` を別候補とし、同一期間・フィルタ・推計条件の母数と全件性を証明できるまでは割合と地図の濃淡を出さない。現 zone の HTTP 系 `availableFields` に `clientRefererHost`（リンク元サイト）と `clientAsn`（接続元ネットワーク）がないため、これらを今回の表示へ採用しない。Web Analytics の referer host は別のページ閲覧系指標で、HTTP リクエストの国別データへ混ぜない。
4. セキュリティ候補は出典、母集団、処理種別を含むか、サンプリング、時間境界、上限、遅延を記録する。`firewallEventsAdaptiveByTimeGroups` 等の時間別総件数は、旧 WAF 処理種別と別系列として評価し、表示名は取得できた値の意味を確認してから決める。
5. 調査結果をデータセット×期間の可否表にする。各セルに「利用可／不可／未確認」、範囲、粒度、完全性、注記、根拠日時を記録する。[証跡](./phase0-evidence-status_20261011.md) に実測と Natural Earth の公開・商用利用、改変、表示義務を記録した。実ファイルの国コード属性・特殊値対応が確定するまで地図の値は実装しない。

## 4. データ契約と安全境界

既存の厳格な v1 検証を土台に、新しい契約版でアクセス時系列・国別分布を**別ブロック**として定義する。旧形式や `summary` から時系列点・国別件数を推測しない。Apps が収集、Portal が版・型・期間・鮮度・由来を検証して表示し、Digest は合意した必須監視対象だけを評価する。契約変更時は両 repo の共通 fixture と版を同じ内容で更新する。

| ブロック案 | 必須内容と検証 |
| --- | --- |
| `traffic24h` | 現行合計とキャッシュ率を維持。0 と null、LIVE と DEMO、期限切れを区別する。 |
| `trafficSeries` | 確認済み期間の開始・終了、粒度、時刻付き点列、HTTP リクエスト数、精度区分。24 時間表示は UTC の直近 **24 個の完了した 1 時間バケット**を対象にし、開始を含み終了を含まない。末尾の未完了時間は点列に混ぜず「集計中」とする。点の順序・重複・範囲・欠損・行数上限を検証し、空白の時間を 0 点に補完しない。現行 `traffic24h` カードと集計窓が違う場合は同一合計と見なさない。 |
| `countryTraffic` | 同一条件の国別値、全体母数、集計方式、上限とカバレッジ、精度区分、`FULL` / `TOP_ONLY` の表示モード。全行取得と同じ条件の母数を証明できた `FULL` のみ割合・地図の濃淡を出す。`TOP_ONLY` は「上位のみ」と明示した件数と順位だけを出し、割合・濃淡を出さない。国コードの確認済み対応表を使い、未知・特殊コードと地図に載らない国・地域も一覧に残す。欠損を 0 か国・0 件とみなさない。 |
| `securityTrend` | Phase 3 で採用が確認できた場合だけ独立追加。旧 WAF 5 項目の形式へ代入しない。 |

契約版は `schemaVersion: 2` とする。Portal が v1 を受け取る間は確認済みの既存ブロックだけを従来の検証で表示し、`trafficSeries`・`countryTraffic` は「未配信」として非表示にする。v2 の新ブロック欠落を 0 件や正常値へ変換しない。両 repo の fixture で v1/v2 と配備順を固定する。

各ブロックは `runId`、source、status (`OK`/`PARTIAL`/`ERROR`/`UNKNOWN`/`DEMO`)、coverage、sampling、`exact` / `estimated` / `unknown` の精度区分、集計期間、取得時刻、期限、閉じたエラー種別を持つ。期間ごとに独立した取得結果とし、ある問い合わせの失敗が他ブロックを消さない。完全性を証明できない部分行・上限到達・GraphQL 部分エラーは正規の全期間値にしない。推計値には推計表示を付け、別方式の値を同一合計や増減として照合しない。24 時間の 1h 系は今回 `sampleInterval=1` だったが、毎回確認する。国別割合は同じデータソース・期間・フィルタ・集計条件の母数から計算し、異なる API の総数や WAF 値を混ぜない。

Digest の必須集合は収集結果自身に決めさせず、Phase 0 で利用可能と確認し採用したブロックを運用設定として固定する。任意・廃止ブロックの `UNKNOWN` は記録するが、必須集合の障害としては扱わない。必須ブロックの `ERROR`・期限切れ・欠落、旧形式しかない状態は正常としない。国別が利用不能なら必須に加えない。

収集は項目別のタイムアウトと問い合わせ予算を設け、既存の GCP・Pages・Digest と障害を隔離する。Phase 0 で現在の設定上限・収集間隔・必要な問い合わせ数を測り、Phase 1 着手前に「1 回の収集で最大何件の GraphQL 問い合わせを許すか」「全体の制限時間」「上限到達時にどのブロックを `PARTIAL` / `ERROR` にするか」を数値で決める。未測定の上限値をここで仮定しない。保存対象は集計済みの国別・時間別値のみとし、IP アドレスや個人のアクセス履歴は保存しない。公開 API の認証・`no-store`・秘密情報非公開を維持する。

## 5. 実装順序と PR 境界

### Phase 1 — 24 時間のアクセス推移と国別地図

- **Apps PR**: `dashboard/cloudflare_collect.py`、`cloudflare_contract.py`、データ生成箇所、fixture、テストを対象に、確認済みの `httpRequests1hGroups` 時間別値と同じ応答の `sum.countryMap` を新契約へ通す。24 個の完了バケット、各時刻の国別和と総数、サンプリング、部分エラーを毎回検証する。旧数値へのフォールバックは作らない。新ブロックの失敗を他サービスの値や別ブロックへ伝播させない。後続の前期間比を採用する場合は、この段階で集計済みの完了バケットの保存を始める。保存キーはデータセット・粒度・期間開始・対象条件で固定し、再実行は同じキーへ冪等に記録する。欠損や部分値を完了値へ上書きせず、遅延確定・再計算時の更新規則と保存先を現運用との照合後に確定する。
- **Portal PR**: `cloudflareCollection.ts`、Cloudflare ページ・専用コンポーネント、契約・UI テストを対象に、カード、24 時間折れ線、世界地図、上位約 10 か国、選択国の件数・割合を表示する。PC は地図とランキングを横並び、スマートフォンは縦並び。一覧を一次の情報源とし、地図は補助表示にする。地図を装飾扱いにするなら読み上げ対象から外し、操作できる設計にするなら名称・件数・操作説明を持たせる。ツールチップと一覧は同じ検証済みデータから作り、読み上げ用の上位国要約を付ける。色だけで値を伝えず、中立的な単色系列を使う。Natural Earth の固定版について実ファイルの `ISO_A2` 等の属性・重複・未対応国・属領を Cloudflare の実コードと照合してから塗り分ける。単純な一対一結合を前提にしない。
- コメントは検証できる事実を 1～2 文とし、比較履歴がなければ「比較データを蓄積中」とする。国は接続元 IP の推定位置であり、VPN やプロキシでは実際の所在地と異なり、訪問者の所在地や悪意を意味しないことを短く示す。新ブロック未配信の間は、その図だけを非表示にし、確認済みカードは残す。

### Phase 2 — 7 日・30 日と前期間比

Phase 0 と[追加実測](./phase2-evidence-status_20261012.md)で**各データセットと各期間**の取得範囲が確認された組み合わせから順次有効化する。7 日・30 日の Adaptive 時間別・国別・全体値は同一区間・同一フィルタで照会し、時間数、両集計の和と全体値の一致、国別行上限未達、重複・部分エラーなしを毎回検証する。今回の一致を今後の保証とは扱わない。前期間比は、Cloudflare 側に当該期間の 2 倍以上の取得可能期間がある場合に限る。比較する両期間で対象・粒度・集計法・推計区分が一致し、欠損・部分値・期限切れがないことを確認する。足りなければ「欠損あり」「この期間は非対応」を理由に応じて表示する。系列の欠損や国別の部分取得を過去値で埋めない。24 時間、7 日、30 日の操作可能状態をそれぞれテストする。

2026-10-12 の[追加実測](./phase2-evidence-status_20261012.md)に基づき、7 日・30 日は Adaptive 系の時間別・国別・全体値を同じ区間・フィルタで照会し、時間別和と国別和が全体値に一致した場合のみ `FULL` の推計値として公開する。時間別はそれぞれ 168 / 720 個の完了した1時間バケットを必須とし、時刻の重複・欠損・境界ずれを拒否する。国別はコード重複、行上限到達、母数不一致、部分応答があれば割合・地図の濃淡を止める。サンプリングがある期間と前期間比には「サンプルから推計」と付記し、24 時間の 1h 系との数値比較はしない。

24 時間の前期間は同じ 1h 系から独立照会し、両方の24点と同一の精度区分を毎回検証する。7 日の前期間は現行窓と独立照会し、両方の168点と全体値を毎回検証する。現行・前期間がともに `OK` / `FULL` で定義・推計区分が一致したときだけ増減を計算する。30 日の前期間は保持境界を超えるため、今回の Phase 2 では履歴を保存せず比較値を出さない。30 日の比較は、保存方式と完全な60日分の蓄積を別フェーズで設計・検証するまで「この期間は比較に非対応」と表示する。「蓄積中」は実際に履歴保存を始めた後だけ使う。

**Phase 2 の契約・配備案（2026-10-12 採用）:** v2 の既存 `trafficSeries` / `countryTraffic` を24時間専用のまま維持し、追加トップレベルブロック `trafficPrevious24h`、`trafficSeries7d`、`countryTraffic7d`、`trafficPrevious7d`、`trafficSeries30d`、`countryTraffic30d` を設ける。各ブロックは既存の取得状態・期間・精度 envelope を持つ。時系列データは `{granularity: "HOUR", totalRequests, points: [{hour, requests}]}`、国別は既存と同じ `{mode: "FULL", totalRequests, countries}`。Apps は同じ Adaptive 応答の時間別和・国別和・全体値が一致した場合だけ `FULL` にし、Portal は受信時に再検証する。国別の件数は行上限500未満、コード重複なし、GraphQL 部分エラーなしを必須とする。各行の `sampleInterval` は有限の1以上とし、一行でも1を超えたブロックは `ADAPTIVE` / `estimated`、全行が1のブロックは `NONE` / `exact` とする。時系列と国別で精度が異なる場合は相互の値を混ぜず、それぞれの精度を明記して独立表示する。比較に使う現行・前期間の精度が異なる場合は増減を表示しない。前期間の `windowEnd` は対応する現行期間の `windowStart` に一致し、取得時刻・期限は現行収集のものとする。7日と30日の失敗は独立させ、24時間表示と他サービスを維持する。Digest の必須集合には採用・有効化した追加ブロックのみを含め、前期間の取得不能は現行期間の障害と区別する。

Portal を先に配備して追加ブロック未配信を期間ごとに表示し、Apps を後から配備する。両側の共通 fixture で 24時間 v2、追加ブロックあり／なし、推計、欠損、部分エラー、前期間の不一致を検証する。国別だけ不完全なら対応する期間の地図・割合のみを止める。前7日だけ不完全なら比較のみを止める。各期間の有効・無効設定と Digest 必須集合を同じ運用設定に揃え、運用中の段階的停止を可能にする。変更は Phase 1 と別 PR にする。

実装上の切替は `CLOUDFLARE_PHASE2_ENABLED` を既定 `false` とし、Portal・Apps の契約と配備が揃うまで追加照会を始めない。明示的に有効化した後は、前24時間・7日・30日をそれぞれ独立した設定で無効化できる。Apps の収集と Digest は同じ設定を読み、無効なブロックは `UNKNOWN`・データなしにして必須監視集合から外す。期間の失敗を別期間の数値で補わない。

### Phase 3 — 参考セキュリティ傾向と運用整理

採用条件を満たす Free のセキュリティ系列があれば小さな独立グラフと事実ベースの短文を追加する。イベント増加を危険・安全、攻撃成功と断定しない。旧 `firewallEventsAdaptiveGroups` 由来の 5 項目は通常画面と**必須監視集合**から外す。Digest は Phase 0 で採用した必須集合の実取得失敗・期限切れ・欠落を検知し続け、廃止した項目の取得不能だけで恒久的に `partial` にしない。旧形式だけが残った状態も新必須データの成功とはしない。Cloudflare 以外の入力、既存 anomaly、last_success、stale 判定を回帰テストで守る。技術情報は「データについて／詳細」へ移し、主画面の危険度・判定不能カードと Pages 利用枠説明を撤去する。

## 6. 検証と受入れ

- **Apps**: 正常な時間別点列、部分時間・遅延確定・途中欠損・重複・境界ずれ・上限・部分 GraphQL エラー・タイムアウト・0 件・DEMO・期限切れを契約テストで確認。国別では未知・特殊コード、地図外の国・地域、部分行、`FULL` / `TOP_ONLY`、同一母数、推計、割合合計を確認。履歴を採用する場合は再実行の重複排除と不完全値による上書き防止を確認。Digest は必須ブロックの欠落・`ERROR`・期限切れ・旧形式のみ、任意・廃止ブロックの取得不能、他サービスの状態を別々に検証する。対象 Python テストと既存 Digest テストを実行する。
- **Portal**: v1/v2・旧形式・不正値・失効・部分取得を検証し、欠けた図だけを止める。`TOP_ONLY` では割合と地図の濃淡を出さない。PC/スマートフォン、キーボード、読み上げ、色に依存しない凡例、選択国とランキングの一致、短い日本語を確認。型検査・UI/契約テスト・Workers CI を通す。
- **連携**: Apps と Portal の fixture が一致すること、Apps 先行と Portal 先行の更新順で偽の値を出さないこと、認証済み実データで 24 時間グラフと国別地図が表示されることを確認。未認証 API は既存 Access 境界を維持。既存 GCP 画面と Digest の状態を確認する。CI 成功は本番定期実行の継続証拠と分けて記録する。
- **受入ゲート**: Issue の 6 条件を個別に判定する。国別 API が利用不可なら地図の完成とはせず、代替源と制約の判断を記録する。7/30 日や参考セキュリティは採用を確認した範囲だけ受け入れる。

## 7. リリースと戻し方

Phase ごとに別 PR とし、Apps の新契約出力と Portal の新契約入力を段階的に配備する。各 PR で対象ファイルだけを commit し、push・merge・本番配備・Issue 完了を別ゲートで判断する。Apps 側には新ブロックごとの有効設定を用意し、国別だけを止めても時系列を残せるようにする。Portal は無効化されたブロックを「未配信」と扱い、0 件にしない。設定方式と初期値は実装前に現行運用と照合する。ロールバック時も旧形式を新ブロックの正常値へ転用しない。WAF/Access/DNS、契約プラン、権限、有料外部 API は変更しない。実データの認証済み PC/スマートフォン確認と次回収集・Digest 実行を終えるまで、継続運転を確認済みと報告しない。

## 8. Phase 1 の実装時照合（2026-10-11）

- Natural Earth v5.1.1 の実ファイルと観測した国コードを照合した。単純な `ISO_A2` 結合は成立しない。描画は有効な `ISO_A2_EH` のみ、対応ポリゴンがない `HK`・`SG` 等は一覧と母数に残す。詳細は[素材検証記録](./natural-earth-map-source.md)。
- Apps の既存 GraphQL 問い合わせ 6 件に 1h の時刻・国別併用問い合わせ 1 件を追加した。各 GraphQL 呼び出しは最大 20 秒、1 回の Cloudflare 収集は既存の REST を含め 64 リクエスト・180 秒で打ち切る。上限に達したブロックは成功値へ変換せず `PARTIAL` または `ERROR` とする。収集頻度・実稼働時間は配備前に再確認する。
- `CLOUDFLARE_TRAFFIC_SERIES_ENABLED` と `CLOUDFLARE_COUNTRY_TRAFFIC_ENABLED` は既定で有効。`false` または `0` で各ブロックを無効にでき、無効ブロックは `UNKNOWN`・データなしの「未配信」とする。収集と Digest に同じ環境変数を適用する。片方だけ有効な場合も同じ 1h 問い合わせから必要なブロックだけを配信する。
- Apps と Portal の共有 v2 fixture と対象テストで、24 点の完了時間、各時刻の国別和、同一母数、v1 互換、独立停止を確認した。本番の認証済み表示と定期収集の継続は未確認。

## 9. 計画レビューと次の判断

複数 repo の契約と Digest の監視意味を変えるため、[Phase 0 の実測表](./phase0-evidence-status_20261011.md) と契約差分を添えて Antigravity の手動再レビューを受け、Codex が内容を照合した。24 時間の時間・国別取得、7/30 日の推計データ、Natural Earth の利用条件は確認済み。Antigravity の「上位 5 か国と total から全件割合が確定」「`ISO_A2` と一対一で結合可能」「Phase 0 未確認事項がすべて解消」は、その抜粋だけでは支持できない。**Phase 1 の 24 時間時系列と 1h 系国別集計は GO、地図の塗り分けは実素材対応の検証まで条件付き、Adaptive の全件割合は NO-GO**とする。残る判断は、地図属性との対応、7/30 日の国別全件性・母数、比較履歴の保存方式、参考セキュリティ系列の意味、OCI 稼働版との差である。
