## 特に確認してほしい点

1. **F1・F2の条件反映**: COLLECTIONが成功してもSIGNALSが未設定なら正常にしないこと、C01〜C05/P01とW01の条件・操作が実装可能であることを確認する。段階提供のユーザー承認を前提に、初回の受入条件と次段階の残課題が混ざっていないか確認する。根拠のない数値の閾値や、未承認の履歴保存を追加しない。
2. **誤った正常判定**: 取得失敗、途中集計、旧形式、モック、未知の版、未知のaction、期限切れ、無効な数値、必須チェック0件で正常になる経路がないか。
3. **部分取得と完全性**: GraphQLエラー、別リクエスト化、上位項目、サンプリング、取得上限、Pagesの全ページ取得の扱いは整合するか。
4. **F3・F4・F6の契約**: 新dataとrunId、前回値を結合しない生成、有効組合せ表、INCOMPLETEとDEMOの追加が整合するか。runId一致だけを由来の証明としていないか。失敗・旧形式で旧数値へ戻る経路がないか。
5. **F7の鮮度**: サーバー送出時刻と単調時計、通信時間を含む保守的な期限判定、スリープ復帰・再同期が整合するか。収集時刻を応答時刻と取り違えないか。未知の運用値が安全に未確認として扱われるか。
6. **意味と説明**: WAFイベントとリクエスト、24時間と7日間、ゾーンとアカウント、PagesとWorkersを混同していないか。パス・ASN・キャッシュ率から根拠のない安全・危険の断定が生じないか。
7. **F8・F12の既存利用箇所**: Digestの無効CF値をunavailableにするだけで全体okになる抜け道がないか。既存collector_errorsへの伝達、他の有効な監視の保持、読取側先行・代替順・ロールバックは妥当か。
