## 地域対応と地図の判断

前作の `feasibility.md` を直接確認。2020年e-Stat境界は名称候補199件一致だが、期間内の区域変更等に関連する8町丁を除くと人口カバー率2016年94.20%・2026年94.41%で、前作の事前95%基準に達しなかった。地理的同一性の確認済みとは扱わない。

今回は確実に成立する町丁別チャートと表を主案にする。最新199町丁の年齢構成と、比較可能性を記録した191町丁の変化を別表示する。8町丁は変化の順位・散布図等から除外するが、最新時点の公式統計と全市総数には含める。除外理由と対象人口を明記する。残る191町丁も境界不変を完全に立証したとは表現しない。

地図は既存境界の問題を解決できた場合だけ採用する。名称候補と地理確認を分離し、町丁数・人口の結合率、未対応と対象地域、境界年・権利を記録する。率の高い主要地域を含め地理確認を終え、町丁数・人口とも95%以上を満たすことを最低条件とし、基準を後から緩めない。未達ならチャート案のまま公開し、タイトルに「地図で」と入れない。この代替はIssue本文の許容範囲内。

小人口の比較は総人口100人未満を順位から分け、表には母数と注意を示す。比較変化は両年100人以上に限る。ゼロ人口・ゼロ分母は率なしとして表示し、0%へ変換しない。

## 集計と記事の実装

1. 原本をgit管理外へ保存。取得URL・UTC/JST取得日時・基準日・SHA256・処理版・ライセンスをmanifestに残す。正式集計は固定原本から再実行できるPythonスクリプトとする。主依存は既存と同じopenpyxl/xlrd、依存の一括更新はしない。
2. 年齢境界を厳密に処理し、0〜14、15〜64、65以上、75以上、85以上、5歳階級を全市と町丁で生成。合計欄や男女/国籍の小計を加算しない。不詳があれば人数を保持し、分母へ含めるか図ごとに明示する。
3. 正規化町名と公式コードを照合。曖昧一致をせず、区域変更8町丁の扱いを前作と突合。欠測は0にしない。最新と過去の全集計、町丁合計、年齢合計を検算する。
4. 都の共通表から6市、都、市部の65/75/85歳以上の人数・割合を算出し、第3-1表との65歳以上合計を突合。都/市部は八王子を包含する集団であることを明記する。
5. 固定JSONを本文・図・表の唯一の数値入力とし、派生CSVと出典manifestを配布する。原本の無条件公開はしない。
6. 冒頭に検算済み発見2〜4点。65歳以上の人数と割合の別図、5歳階級比較、近隣市比較、町丁の率/人数切替と総人口併記、方法・限界、関連記事を構成する。75/85を含む帯図は0〜14/15〜64/65〜74/75〜84/85以上の重ならない区分とする。
7. 全グラフに基準日・単位・分母、文章の要点、HTML表を付ける。町丁選択と切替をスマホ・キーボードでも使えるようにする。色に加えてラベル・数値・選択表示を用いる。因果・衰退・住みやすさ・政策効果・将来予測は断定しない。
