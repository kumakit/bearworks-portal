# Issue #403 改訂計画の手動再レビューへの対応

2026-10-17 JST。レビュー担当者は計画と証跡・初回対応記録を読んだ。API、コード、本番、GitHub Issue は再確認していない。以下は Codex が手元の Apps コードと追加証跡に照らして判断した結果。対象: [実装計画](../task/issue-403/implementation_plan.md)、[追加証跡](../task/issue-403/phase0-additional-evidence_20261017.md)。

| 指摘 | 判断 | 反映と理由 |
| --- | --- | --- |
| 1-1 回復可能な障害長 | 一部採用 | `L − W − T − S` を条件付きの上限見積りとして記した。73時間の起点が未確認なので厳密な最大長とは呼ばず、境界実測を設計ゲートにした。 |
| 1-2 通知期限 | 採用 | 回復可能な時間の半分以内を目安に、回復不能になる前の通知を定める。正確な閾値は `L` と `W` の実測後。 |
| 1-3 時間ごとの状態 | 採用 | 未収集、仮値、確定値、欠測、回復不能、保存失敗と、正当な0件を区別する。 |
| 1-4 境界の1時間差 | 採用 | 約70～75時間前を1時間刻みで少量照会し、遡及上限の起点と72時間の照会上限を別々に確認する。 |
| 1-5 初回値の扱い | 採用 | 時間終了からの経過時間を保存し、初回値は仮値とする。 |
| 2-1 時間差の実測不足 | 採用 | 曜日・時間帯を変えて複数日、15分～72時間の同一時間の件数差・割合・抽出情報を集計する。凍結規則が決まるまで保存実装に進まない。 |
| 2-2 観測と採用値の分離 | 採用 | 2表に分ける。同じ観測の識別・重複排除は実装前に決めるが、ハッシュ方式を唯一の方法にはしない。 |
| 2-3 凍結後の変化 | 採用 | 維持、改訂、凍結延長の選択を実測後に固定する。 |
| 2-4 `sampleInterval` | 一部採用 | 現行 `cloudflare_collect.py` は1時間集計でフィールドを要求し、数値型・範囲を検証する。実環境の再照会でも数値として返った。頻度と時間差の調査は続ける。 |
| 2-5 5組の出典 | 採用 | 5組は Adaptive の再照会であると証跡に明記。1時間集計の安定性には流用しない。 |
| 3-1 欠測と未確定末尾 | 一部採用 | 許容欠測0時間を明記し、末尾を確定済み時間に揃える。既存の「連続720/1440時間」と整合するため、追加の安全ブロッカーというより公開時期の条件。 |
| 3-2 24時間とのずれ | 採用 | 現行24時間を維持し、未確定末尾と履歴の確定値が一時的に違い得ることを示す。24時間の履歴移行は今回の範囲を広げるため保留。 |
| 3-3 切替時の不連続 | 採用 | 切替日と以前の数値との差があり得る旨を画面に示す。 |
| 3-4 国別の出典 | 一部採用 | 24時間国別は1時間集計と同じ応答、7日・30日国別は Adaptive。注記は出典が異なる30日表示に絞る。合計は異なる場合がある。 |
| 3-5 推計行と比較 | 採用 | 抽出頻度を測り、推計行を含む窓の比較条件を再判定する。 |
| 4-1 保存失敗の隔離 | 採用 | 現行コードは `data.json` を処理の最後に書く。新しい任意処理は公開成功後の独立経路とし、終了コード・Digest 判定を壊さない契約を置く。 |
| 4-2 #397 との分離 | 採用 | Adaptive 30日収集の修正を #397 側の別変更とし、#403 の履歴処理は依存させない。 |
| 4-3 波及テスト | 採用 | 24時間・7日間・各期間の国別表示を個別に確認する。 |
| 5-1 バックアップと復旧目標 | 採用 | 独立先と復旧演習を本番保存の前提にした。損失最大約1時間・復旧24時間以内を提案値として、費用と運転実績を確認して決める。 |
| 5-2 容量の重点 | 一部採用 | 基本の時間行は少ない見込みだが、小容量とは確定しない。改訂履歴・WAL・バックアップ世代まで見積もる。 |
| 5-3 別のバックアップ候補 | 採用 | OCI Object Storage と別端末からの定期取得を比較する。後者も常時稼働・通知・復旧担当が必要。 |
| 5-4 権限とロック | 採用 | DB・WAL の非公開性、ファイル権限、バックアップ時のロックと整合性を確認する。 |
| 6-1 時刻と期限のテスト | 採用 | 時刻注入と期限を模した応答を加え、実 API の境界は別途読み取り照会する。 |
| 6-2 非公開の比較期間 | 採用 | 保存後、公開前に履歴と既存表示との差・欠測を観測する。 |
| 6-3 復旧手順 | 採用 | 戻し方に別パスへの復旧と整合性照合を加えた。 |
| 6-4 蓄積中の文言 | 採用 | 欠測があると切替時期が延びる旨を画面文言に加えた。 |

この再レビューを受領し計画へ反映した。ただし、時間別値がいつ安定するかと独立バックアップの実在・権限・費用は未確定。実装前の調査と本番保存のゲートを維持する。

対応後の単発読み取りでは、正時から72時間前に始まる1時間は取得でき、73時間前は GraphQL エラーになった。同じ24時間の両データセットの合計の絶対差は2.5%だった。[追加証跡](../task/issue-403/phase0-additional-evidence_20261017.md)に条件と限界を記した。これは凍結待ち時間や独立バックアップの未確認を解消しない。
