# Issue #397 診断ログの Sonnet レビューと採否（2026-10-13）

ユーザーから Apps PR #20 と Portal PR #27 に対する Sonnet の読み取りレビューを受領した。結論は条件付き承認。レビュアーはPR差分を読み、テストは実行していない。Issue本文は誤ったrepoで照会しており未確認だったため、司令塔が `kumakit/mission-control#397` の本文を確認した。レビュー中の `gh` 読み取りはレビュアーの手順境界から逸脱していたが、リポジトリ・GitHub・本番への書き込みは報告されていない。

| 指摘 | 採否・理由 | 変更先 |
| --- | --- | --- |
| 診断の失敗で本処理が失敗しうる | 採用。診断生成・出力を例外から隔離し、既存の収集・Digest判定を保持する。 | Apps `cloudflare_diagnostics.py`、両呼び出し、対象テスト |
| 収集とDigestの実行ID伝播が未検証 | 採用。実際の `collect()` 出力を使うテストで同じIDを確認する。本番ログの一致は配備後に確認する。 | Apps 収集テスト、運用書 |
| 有効項目の判定重複 | 採用。機能フラグを収集で一度だけ読み、収集とログへ同じ値を渡す。必須項目の選択をDigestと共通関数にする。 | Apps 収集・Digest・診断モジュール、テスト |
| 無効項目、Cloudflare側の可否、時刻の表現 | 採用。`disabled` と `cfAvailable` を追加し、時刻を正規化する。`cfAvailable` はDigest全体の結果ではない。 | Apps 診断モジュール、運用書 |
| 秘密値非出力テスト、欠損・旧schemaのテスト | 採用。任意文字列、欠損、旧schema、フラグ組合せ、例外時の判定不変を追加する。 | Apps 対象テスト |
| `INVALID_CONTRACT` の細分化 | 一部採用。欠損ブロックと期限情報欠損を分ける。Adaptiveの別集計不一致は収集側の `PARTIAL_RESPONSE` で示し、それ以上の原因は実測まで推測しない。 | Apps 診断モジュール・計画 |
| ログ量・出力先・保持期間 | 一部確認。収集とDigestはコード上INFO。収集ジョブから`cron.log`へのリダイレクト、週次8世代の設定と既存世代を読み取り確認。Digestはjournalで、実保持日数は未確認のまま運用確認項目に残す。 | Apps 運用書・計画 |
| 計画と実装、戻し方、件数表現のずれ | 採用。正常時も全項目の状態を記録する設計、新規ファイルの扱い、`usableCount` の意味を明記する。 | Portal 計画 |
